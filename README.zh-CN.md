# Chora

**让人与 AI Agent 一起开发软件的开源协作工作空间。**

[English](README.md) | **简体中文**

[快速开始](#快速开始) · [第一个任务](#第一个任务) · [常见问题](#常见问题) · [项目进度](#项目进度) · [文档](docs/README.zh-CN.md)

描述你想做的改动，观察 Agent 执行，查看代码差异和检查结果，再决定提交和发布。
Chora 在本机浏览器工作台中，把仓库、对话、任务和审阅历史放在一起。

Chora 的最终定位是可私有部署、不绑定特定模型的协作开发工作空间，让人与 Agent
跨项目、跨仓库完成规划、开发、审阅和交付。目前提供的是通过源码运行的
**开发者 Alpha**，支持 Apple Silicon macOS 和 Pi。已实现能力与后续计划见
[项目进度](#项目进度)。

## 你可以用它做什么

- **跨仓库完成任务。** 在一个项目中关联多个本地 Git 仓库，为每个任务选择需要使用的仓库。
- **看见执行过程。** 随时查看计划、进度、检查和待回答的问题，按需取消或重试。
- **审阅后再发布。** 在独立任务分支和工作树中查看改动，逐步确认提交、推送、PR 和合并。
- **继续之前的工作。** 重启后重新打开项目、话题对话和任务历史。

```text
描述需求 → Agent 执行 → 审阅差异和检查 → 提交 → 推送 → PR
```

## 快速开始

### 1. 准备环境

使用 **Apple Silicon Mac**，并确保终端中可以使用以下工具：

| 工具 | 版本或用途 |
| --- | --- |
| Git | 克隆 Chora，管理本地仓库 |
| Node.js | 22.19 或更新版本，Pi 运行需要 |
| npm | 11 或更新版本 |
| Go | 1.26 或更新版本 |
| 模型访问权限 | 在 Pi 中配置你自己的服务商凭据或订阅 |

这条启动路径不需要 Docker。只有需要在 Chora 中创建或合并 GitHub PR 时，
才需要安装 GitHub CLI（`gh`）。

### 2. 构建并启动 Chora

```sh
git clone https://github.com/Yangyang96/chora.git
cd chora
npm ci
npm run web:build
go run ./cmd/chora workbench --source "$(pwd -P)"
```

终端出现 `Chora Workbench listening on http://127.0.0.1:8787` 后，
在浏览器中[打开 Chora](http://127.0.0.1:8787)，并保持终端运行。
可以通过应用内的语言切换按钮选择中文或英文。

按 `Ctrl-C` 停止服务。再次使用时，在同一目录运行上面最后一条命令即可。
数据保存在 `~/.chora/data`。

### 3. 为 Pi 配置模型

Pi 是为 Chora 执行编程任务的 Agent。

1. 打开 Pi 安装面板。Chora 可以复用 `PATH` 中已有的兼容 `pi`；如果没有，
   点击 **安装固定 Pi 版本**，安装 Pi 0.85.1。
2. 在另一个终端中运行面板显示的配置命令。如果复用的是 PATH 中的 Pi，命令就是 `pi`。
3. 在 Pi 中使用 `/login` 配置服务商，再用 `/model` 选择模型。
4. 回到 Chora 点击 **刷新**。如果面板提示需要重启，按 `Ctrl-C` 停止 Chora，
   再运行启动命令。

这条路径使用 **可信本地 · 无沙箱**（Local Connected）模式。开始前请阅读并确认应用内说明：
Pi 直接在本机运行，可以访问本地工具、文件、凭据和网络。任务工作树用来分开代码改动，
不提供安全沙箱隔离。模型请求会发送到你配置的服务商。

## 第一个任务

先在可信仓库中尝试一个小改动，例如修正校验提示或补充一条测试。

1. **创建项目。** 通过文件夹选择器选中一个已有本地 Git 仓库，仓库至少需要有一次提交。
   之后可以继续添加其他仓库。
2. **打开默认的 General 话题空间（Room）。** Room 用来组织同一话题的对话和任务；
   项目变大后，可以为不同话题新建 Room。
3. **描述改动。** 选择仓库和目标分支。检查策略可以保留自动发现，也可以选择命名检查，
   或明确选择不运行检查。无需逐个列出 Agent 可以修改的文件。
4. **开始并观察任务。** Chora 会创建任务分支和工作树。查看计划与进度，必要时回答待决问题。
5. **审阅结果。** 阅读代码差异和检查结果，接受改动或要求修复。接受后，改动保留在任务工作树中，
   不会自动提交、推送，也不会写回原始仓库目录。
6. **准备好后交付。** 对每个仓库逐步预览并确认 **提交 → 推送 → GitHub PR → 合并**。
   PR 操作需要已登录的 `gh`；提交和推送使用你的 Git 配置。确认 PR 已合并、任务工作树干净后，
   才能执行工作树清理。

Pi 报告的检查会标注为 **Agent 报告**；缺失或未观察到的检查保持 **未验证**。
请查看实际结果，再决定是否发布。

## 不配置模型，先体验界面

完成前面的克隆、依赖安装和构建后，用下面的命令替代 Workbench 启动命令：

```sh
CHORA_DEMO_ROOT="$(mktemp -d /private/tmp/chora-demo.XXXXXX)"
go run ./tools/e2eserver \
  --db "$CHORA_DEMO_ROOT/chora.db" \
  --web "$PWD/web/dist" \
  --port 8787
```

在浏览器中[打开本地演示](http://127.0.0.1:8787)。演示使用预设脚本，不调用模型，
也不会执行真实 AI 编程。启动前请先停止占用 8787 端口的其他 Chora 服务。
按 `Ctrl-C` 停止；临时数据不会自动删除。

## 常见问题

### 会修改我原来的仓库目录吗？

新任务在 `~/.chora/data/task-workspaces/` 下的独立 Git 工作树中执行。
接受审阅后，改动留在任务分支上；发布是单独的操作。
原始仓库中尚未提交的改动不会复制进任务使用的已提交基线。

### 任务数据存在哪里？

项目、任务和历史记录保存在 `~/.chora/data`，受管理的任务工作树也在其中。
重启时使用同一数据目录，就可以重新打开之前的工作。
可通过 `--data /absolute/path/to/data` 指定其他绝对路径，但必须放在 Chora 源码目录之外。
移动、删除或升级数据前，请阅读[备份与恢复说明](docs/workbench-maintenance.zh-CN.md)。

### Pi 未就绪，或者页面打不开，应该检查什么？

用 `node --version` 检查 Node 版本，完成 Pi 登录和模型选择，再刷新安装面板；
如果有重启提示，请按提示操作。如果 8787 端口已被占用，在启动命令后添加 `--port 8788`，
并在浏览器打开对应端口。其他问题参见[故障排查与诊断](docs/workbench-maintenance.zh-CN.md)。

### 支持 Linux、Windows、其他 Agent 或沙箱吗？

目前真实 Agent 上手路径是 Apple Silicon macOS 上的 Pi。
跨平台 CI 通过不代表其他系统上的完整工作流程已获支持。
保留的 Docker 隔离路径需要维护者私有输入，不是公开安装选项。
其他服务商和部署方式见[路线图](ROADMAP.zh-CN.md)。

### 目前支持哪些代码改动？

任务可以跨所选仓库新增、修改、删除和重命名普通 UTF-8 文本文件。
目前会拒绝二进制文件、Git LFS 内容、子模块和可执行权限的变更。
依赖不会自动安装；任务需要环境准备时，请明确声明相关命令。
多仓库交付逐仓库进行，不支持跨仓库原子合并。

## 项目进度

**截至 2026 年 9 月 10 日：** 源码已公开，当前处于开发者 Alpha 阶段。
源码公开不代表稳定版发布，也不代表最终用户验收已经完成。

| 方向 | 当前进度 |
| --- | --- |
| 个人工作空间 | 已实现多仓库项目、话题空间、任务分支与工作树、执行过程展示、审阅、重试及重启恢复。 |
| 代码交付 | 已实现逐仓库提交 → 推送 → GitHub PR → 合并 → 清理，各步骤单独确认。 |
| 上手与维护 | 已实现 Pi 安装配置引导、模型来源展示、备份恢复和本地诊断。 |
| 当前支持环境 | Apple Silicon macOS、源码运行、本地 Git 仓库，以及明确选择 Local Connected／无沙箱模式的 Pi。 |
| 发布准备 | 源码已公开，已有本地验证；最终用户验收和带 Tag 的版本发布仍待完成，暂未提供桌面安装包。 |
| 后续拓展 | 公开可用的沙箱配置、更完整的模型控制、团队与多 Agent 协作、后台及远程任务、更多 Provider 支持。 |

完整协作工作空间是产品方向；团队权限、多 Agent 委派和远程执行尚属后续计划。
各阶段的长期规划与历史背景见[路线图](ROADMAP.zh-CN.md)。
