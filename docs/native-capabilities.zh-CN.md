# Local Connected 中的 Skills 和 MCP

[English](native-capabilities.md)

项目的 **Skills 和 MCP** 管理已有本地 Pi 资源的引用，作用于该项目所有 Room 的新
Local Connected 执行，不修改全局 Pi 文件或其他项目。Isolated Local 不加载这些
资源，本切片不支持为该模式配置 Skills/MCP。

验证版本为 Pi 0.85.1，以及可选的
[`pi-mcp-adapter@2.34.0`](https://github.com/nicobailon/pi-mcp-adapter/releases/tag/v2.34.0)
扩展。Pi 不内置 MCP 客户端。使用 MCP 管理前，请自行通过 Pi 安装桥接扩展；Chora
不安装或更新包。若发现操作无法从已启用的 Pi 扩展中找到它，可以填写其本地包目录。

## 配置项目

打开项目并展开 **Skills 和 MCP**，填写已有 Skill 文件或目录的绝对路径、可选的桥接
包目录，以及可选的现有 MCP 配置文件路径。**禁用的 Skill 路径**填写发现结果中的
准确 Skill 文件路径；**禁用的 MCP 服务名称**填写服务标识。首次保存后，后续执行
启用项目能力管理；没有保存配置的项目保持原有的 Pi 原生加载行为。验证前先保存配置。

默认继承全局资源。项目禁用项仅作用于本项目，移除禁用项恢复继承。原生仓库级发现
结果可能随任务工作区不同而变化。项目发现视图显示全局资源和显式项目引用，各执行
的观察状态则描述自己的工作区。这些扩展使用 Local Connected 现有的 **No Sandbox**
权限；外部指令或工具结果不会获得覆盖任务契约的权限。

Chora 保存引用和禁用项，不保存引用文件的内容或凭据。认证通过已有 Provider／桥接
配置或环境完成，Chora 不提供 MCP 密钥表单或 OAuth 登录流程。需要认证的服务在
修复认证之前保持不可用。

## 检查与恢复

**刷新状态**只读配置，不连接服务或调用扩展。**已发现**、**已缓存**和**尚未连接**
不代表连接当前可用。用户主动禁用，与已启用但加载失败，是不同状态。

**验证／重试连接**启动临时 Pi 会话并执行原生桥接重连命令，可能启动已配置的本地
MCP 进程或连接远程服务；不调用模型、业务工具，也不重载已有执行。结果仅描述本次
检查，不能保证之后的任务仍有相同连接。

失败或需要认证的服务不可用，其他能力仍可继续。项目页显示各执行的观察状态，任务页
在记录的能力不可用时提示。修复源配置或认证后可重新验证，变更对新执行生效。
显式恢复会话复用原项目配置；如果资源或配置指纹变化，会拒绝恢复，此时应开始新执行。
指纹覆盖已加载的 Skill 文本和验证版本桥接扩展的运行源码，不保证任意第三方扩展依赖
或外部服务实现的完整性。已经停止的执行只展示上次观察结果，不表示连接仍然在线。

## 验证

配置测试覆盖持久化、乐观并发、非法输入、归档保护和项目隔离，浏览器测试覆盖配置流程。
已在本地安装验证版本后，可运行：

```sh
CHORA_TEST_CAPABILITY_PI="$(command -v pi)" \
CHORA_TEST_CAPABILITY_BRIDGE="/absolute/path/to/pi-mcp-adapter" \
go test ./internal/nativecapabilities -run 'TestRealPi' -v
```

测试使用临时数据，在无模型凭据的情况下检查 Skill 可用性、全局与项目 MCP 配置，
以及正常、失败和禁用服务。未设置上述环境变量
时会明确跳过；普通单元测试不能证明本机安装可用。
