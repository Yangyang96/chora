## 1. 决策与建设顺序

给现有 Task 增加原生视图，而不是再建一个议题系统。Project 拥有资源，Room 组织主题与
上下文，Task 承载工作，看板组织注意力。保持 Provider 拥有模型/工具循环，以及已有执行、
审阅、交付和授权契约。

顺序为 **M2-S6 本地实现 -> M2-S6A V0 -> M2-S7**。S6A 是插入的有界切片，不重编号
S7，也不重新打开 S6 验收。它不等待正式 macOS 分发、暂缓的全部 S4-2 档位、M3 或 M4，
不成为新的首版 Alpha 发布门槛。

价值假设是减少寻找待决策、待审阅、待恢复、待交付工作的成本，不需要人工同步任务状态。
这不是已经测得的留存、Agent 质量或 token 效率提升。

## 2. 范围与非目标

| V0 包含 | V0 不包含 |
| --- | --- |
| Project 内跨 Room 聚合已有 Task | 第二套 Issue/Card 身份或看板状态数据库 |
| 看板/列表切换，Room 与仓库筛选 | Backlog 草稿、优先级、自定义字段、手动排序 |

| 需要处理、准确子状态、下一步导航 | 拖拽执行、接受、合并或批量写操作 |
| 只读摘要、有界刷新、过期数据恢复 | Agent 分配、认领、依赖和自动委派 |
| 中英文、键盘及窄窗口可用性 | 调度器、第二模型循环、远程 Worker 或外部看板同步 |

已有 New Task、归档/恢复、Review、重试、交付和清理流程继续可达，保留原有保护。
V0 不新增卡片内写操作捷径：卡片动作打开原有归属页面，由该页面重新读取当前状态后
提供操作。查看、筛选和刷新不调用模型，不准备工作树，不启动任务。

多仓库、多 Run、多 Attempt 仍然一个 Task 一张卡，Agent 内部步骤留在详情里。
现有 Room -> New Task -> 执行路径不强制绕经看板。这是第一个编码视图，不要求未来所有
工作类型都创建 PR。

## 4. 用户路径与布局

Project 增加 **Tasks（任务）** 视图，包含看板和列表模式；保留项目资源管理与 Room
导航。Room 使用同一展示组件，只是锁定自身范围，不能变成生命周期列。
从 Project 进入原有新建任务流程时，默认 Room 继续作为默认归属。

五个阶段组为 **Preparing | Working | Review | Delivery | Finished**，对应
**准备中 | 处理中 | 待审阅 | 交付中 | 已结束**。这些是派生阶段，不可直接编辑。
处理中不代表 Agent 进程此刻在运行，已结束不代表成功。任务可以回退或跳过阶段。

卡片展示标题、Room、仓库名称/数量、阶段、准确子状态、需要处理的原因、下一步与最近
活动时间。模型/来源、Attempt 历史、检查与日志留在已有 Task/Run 详情。只展示识别动作
所需的最小 Gate 摘要，不携带原始上下文。

**需要处理** 是跨阶段筛选，不是第六个生命周期阶段。已结束任务保持紧凑且可筛选。
归档 Task 默认不显示，可显式查看；归档 Project/Room 可读，但不能授权新工作。
空 Project 仍支持正常项目初始化。

只持久化非权威视图偏好；筛选写入导航状态或 URL，使深链接与返回操作保留范围。
尽量保留卡片焦点和滚动位置，刷新不得夺取键盘焦点。使用文字及可访问控件，不只依赖
颜色。窄窗口使用同源列表或纵向分组，不要求拖拽。

## 5. 投影契约与判定优先级

返回稳定的结构化字段，不把翻译文案当逻辑。建议的最小卡片契约为：

```text
identity: projectId, roomId, taskId, title, repository summaries
source: latestRunId/version, latestAttemptId when present, observedAt
phase: preparing | working | review | delivery | finished | null
substate: stable reason code + localized display parameters
attention: none | required | unknown, reasons with evidence targets
outcome: null | delivered | applied_locally | no_change | closed |
         partially_delivered_closed | mixed_delivery | cancelled | superseded
nextAction: kind, owning URL, identity/version target, availability reason
visibility: taskArchived, roomArchived, projectArchived, readOnly
health: current | stale | unavailable | inconsistent
```

这是读模型，不是持久化工作流或权限授予。可选来源字段必须有事实依据，不虚构 Attempt、
审阅者、负责人或交付身份，保持 Runtime 中立。只有满足下文适用条件时才输出结束类型。

判定顺序：

1. 校验范围、归属和适用关联；一致地读取当前 Task、适用计划、当前 Run/Attempt、
   Gate/Review、关闭与各仓库交付事实。旧版和资源结果路径显式适配。
2. 遇到不支持、不可用或矛盾事实，使用 `phase=null`、`attention=unknown`，放入五列之外
   的 **Needs reconciliation / 待核对** 分组。保留任务和计数，不悄悄丢弃，也不默认归入
   准备中或已结束；其他有效任务仍可用。
3. 依据当前工作，不依据任意历史终态 Run。存在已授权且仍活跃的后继工作时，旧 accepted
   Run 不能结束 Task。按实际支持的契约处理后继计划或关联 Task 路由。
4. 对已接受结果聚合所有适用仓库。`Task.closed`、`Run.accepted`、`terminalAt`、
   `resultClosed`、清理状态和缺少下一步按钮，都不能单独证明成功交付。
5. 得出阶段/结束类型，再叠加独立的注意事项、归档和只读状态。过期信息不升级结果，
   不授权操作。

投影须覆盖已知与未知输入：每个范围内 Task 必须成为一张卡或可识别的待核对条目。
GET 不得顺便修复底层记录。

## 6. 生命周期映射

下表在有效性、关联和当前工作选择完成后适用，不是对 `Run.status` 的无条件 switch。

| 当前权威事实 | 阶段 | 必须保留的区别 |
| --- | --- | --- |
| 尚无 Run，初始计划准备或首次启动就绪有效 | 准备中 | 编辑计划、计划审阅、资源准备、待启动是不同子状态，不是 Backlog。 |
| 首次 Run 为 `draft` / `ready`，没有执行历史 | 准备中 | 资源准备失败需要注意，不能谎称就绪。 |
| 执行后的重试进入 `ready` | 处理中 | 等待重试/继续，不能显示成从未开始。 |
| `running` | 处理中 | 区分执行与等待当前必要 Gate；仅实际执行显示运行活动。 |
| `stopping` | 处理中 | 正在停止不是已停止，不确定停止需要核对/恢复。 |
| `awaiting_verification` / `verifying` | 处理中 | 等待检查与检查中有区别，保留不可用/不适用语义。 |
| `recovery_required` / `verification_recovery_required` | 处理中 | 需要恢复；自动重试活跃与耗尽/阻塞不同。 |
| `revision_required`，有效的实现重试/资源结果拒绝 | 处理中 | 请求修改然后重试，不是仍等待接受结果。 |
| 有效的 `continue_successor_plan` 路由 | 准备中 | 当前 Task 内重新规划，保留历史 Run。 |
| 有效的 `open_related_task` 路由 | 原 Task 依据自己的处置状态 | 新 Task 独立成卡并链接前驱；关联本身不能结束原 Task，只有明确结束事实才可标 superseded。 |
| 当前结果 `awaiting_review` | 待审阅 | 任务结果审阅，不是方案审阅或外部 PR 审阅。 |
| 结果已接受，仍需 Commit/Push/PR/Merge 或本地 Apply | 交付中 | 展示真实待执行动作；接受不等于发布。 |
| 结果已接受，但适用仓库仍待审阅 | 待审阅 | 保留仓库细节，不把未完成审阅藏在成功状态里。 |
| 交付错误、外部操作结果不确定、PR 未合并就关闭 | 阶段事实可知时为交付中 | 需要处理；无法确定阶段事实时进入待核对。关闭 PR 不是合并。 |
| 部分仓库结束/关闭，但其他仓库仍有工作 | 交付中，或上述待审阅 | 展示逐仓库进度，不依赖一个关闭布尔值判断结束。 |
| 全部适用变更仓库满足下方交付规则 | 已结束 | 区分已交付、本地应用、混合方式或关闭类结果。 |
| 现有无变更路径产生 `completed` | 已结束 | 无变更结束，不额外声称人工接受、代码合并或超出证据的需求满足。 |
| `cancelled`，Task 仍开放可继续且没有明确结束事实 | 处理中 | 已停止/可重试，不自动继续，也不自动结束。 |
| 有明确取消/关闭结束事实，且无后继或未解决工作 | 已结束 | 取消/关闭，不默认当作绿色成功。 |
| Task/Room/Project 归档 | 底层阶段不变 | 可见性/只读叠加，不是完成事件。 |

### 交付完成规则

正常 Task-branch 路径中，**交付完成指已有支持的合并证据证明变更已集成到选定目标**。
Commit、Push、打开 PR 都是中间成果，不是集成。此规则是 V0 展示决策，不是新的运行终态，
也不是部署声明。受支持的旧版本地写回路径，已证明的 Apply 对应独立 `applied_locally`
结果，不能称为合并或上线。全部仓库分别通过 merge 和本地 Apply 混合完成时使用
`mixed_delivery`，保留每个仓库实际达到的终点。

检查绑定结果/范围内的每一个仓库。只读/无变更不产生交付工作，但证据不可用不能等同于
无变更。某种契约确实没有交付要求时，需要从契约确认，不能由缺少摘要推测。
历史 legacy 记录证据不足时，明确保留为待核对。

显式关闭只有在已有资格检查与操作核对证明不再有未解决动作时，才能结束剩余工作。
部分仓库集成、其他仓库放弃，应为 `partially_delivered_closed`，而不是 `delivered`；
即使未集成，也保留本地提交/推送成果。一个仓库已关闭、另一个 PR 仍打开时继续归交付中。
外部 PR 关闭不能自动当作 Chora 结果关闭。

清理是独立维护。全部集成但尚未清理可归已结束，详情仍提供清理操作。工作树已清理并不能
证明合并，必须看保留的成果证据，包括放弃后的清理。清理失败仍提示注意，但不抹掉已证明
的交付结果；不能把源码/交付证据不确定伪装成单纯清理问题。

## 7. 注意事项与动作规则

当前必要阻塞 Gate、可执行的结果审阅、恢复/返工或交付动作进入需要处理。文案区分方案
审阅、结果审阅和外部 PR 审阅。非阻塞风险/未知项仅作信息，不自动阻塞。自动重试活跃时
保持处理中，耗尽/阻塞时提示处理。可选清理是维护，不代表交付未完成，但清理失败仍需提示。

已解决 Gate 不再产生待处理动作，重新打开/当前 Gate 使用当前身份和版本，历史 Gate
不能重放执行。回答、审阅、重试进入原有 Task/Run 页面。归档上级抑制执行操作但不隐藏
未解决事实。动作资格未知或不可用不能显示成“不需要操作”。

`currentAction.kind=none`、成功颜色、Agent 自报检查和普通状态文案都不是验收证据。
服务端授权、期望版本、幂等和确认仍是最终边界。

## 8. 只读 API、刷新与生命周期接入

建议接口：`GET /api/v2/projects/{projectId}/task-board`，支持可选 Room/仓库、阶段、
注意事项、归档筛选及 cursor/limit。实现前核对路由风格；这些参数不是现有 API 声明。
返回卡片、完整筛选范围总数、阶段/注意事项/待核对计数、新鲜度与后续游标。
Room 范围展示复用同一推导与接口契约。

校验所有 ID 属于当前 Project，跨项目 Room/仓库参数不得扩大访问范围。保留现有本地
认证、来源和只读规则，不新增公开监听接口或远程权限。

采用有界批量摘要读取，不能逐 Room/Task 发 HTTP 请求，也不能逐卡加载完整 Run 日志、
diff 和制品。渲染看板不调用 Pi/模型、GitHub 核对命令或工作区准备。读取已持久化的交付
观测，显示新鲜度，由已有详情流程负责核对。

先推导/筛选再分页，计数描述完整筛选集合而不是当前页，单次响应来自同一个一致快照。
按活动时间与 Task ID 等稳定键排序。必要时刷新使旧分页失效并重新加载，以 Task ID
去重；未实现跨页快照隔离时不得声称有此能力。初始默认每页 50、上限 100，这是设计默认值，
不是已测容量。

复用有界轮询，初始目标为可见时每两秒一次；每视图最多一个在途请求，范围变化时取消，
聚焦/重连/操作返回时立即刷新，忽略旧范围的迟到响应。刷新失败立即标记过期，保留最后
状态与观测时间；详情导航继续可用，但不能用过期数据提供可直接执行的动作捷径。
没有有效快照时显示不可用，不是空 Project。隐藏页面不轮询；恢复显示先读取，不静默恢复执行。

**页面切换验收：** 检查 `newApp.tsx` 中依赖 Run 路由的自动验证 effect，证明离开 Run
进入看板不会让已授权检查停滞、重复启动验证或取消工作。如果证实存在路由耦合，只对已有
执行/服务归属做保证连续性所需的最小改动并补回归。GET 必须只读，看板不能成为调度器。
不增加排队任务、自主授权、崩溃后自动恢复执行或远程运行。

保持 S6 关标签后的服务归属、菜单重开、正常退出，以及 S5 预览生命周期。暂停后台标签
轮询不是停止 Agent/应用的授权。重启后读持久事实，不自动重启预览，不改变已有恢复规则。

## 10. 必须覆盖的验收矩阵

这些是需要实现/执行的测试，**不是已经取得的结果**。

| ID | 场景 | 必须满足 |
| --- | --- | --- |
| B01 | 空 Project 与多个 Room | 正常空状态，一个 Task 一张卡，不增加 Room 归属。 |

## 11. 后续扩展

**V1，在 M3 前后按需求触发：** 反复出现记录未来工作的需要后，再建设轻量草稿与排序。
创建草稿不是执行授权，不在记录时建立工作树、调用模型或冻结容易过期的执行基线。
转成正式 Task 时建立可追溯关联，不能维护两份独立可编辑的需求。

**M3：** 人/Agent 分配、认领、交接、委派、依赖，需要成员、撤销、并发和授权规则。
负责人不是执行授权。**M4：** 排队/后台/远程、预算和通知，需要真实执行归属。
这些都不是 V0 的隐含工作。
