# 按需应用预览

[English](app-preview.md)

代码、diff、检查和 Review 仍是日常验收流程。应用预览用于在 Agent 完成后按需查看
Web 应用效果，不会批准结果、计为检查通过，也不是交付的必要步骤。

## 使用预览

1. 打开 Task 最新的运行，展开**应用预览**。
2. 选择可写的 Task 仓库。Chora 读取 `package.json` 中的 `dev` 和 `start` 脚本作为
   建议，不执行脚本；也可以手动输入其他命令。
3. 核对命令、相对仓库的工作目录和应用端口，保存配置或主动选择**启动预览**。
4. 在独立浏览器标签页打开应用，在 Chora 查看日志。
5. 用完后选择**停止预览**。预览清理只移除临时资源并保留配置，不删除代码。

配置端口必须与应用实际使用的端口一致。Chora 提供 `PORT` 和 `HOST` 环境变量，
部分框架需要显式命令参数。例如 Vite 可用
`npm run dev -- --host "$HOST" --port "$PORT" --strictPort`。
命令通过 shell 运行。启动前请核对发现的建议；建议不代表应用或依赖已就绪。

Chora 不自动安装依赖。启动失败时，查看日志，修正命令或在对应环境准备所需依赖。
进程运行不代表应用已就绪或功能正确，实际结果由浏览器和日志呈现。

## 执行模式

**Local Connected** 使用本机工具和环境，在校验过的 Task 工作区执行明确的命令。
该模式为 **No Sandbox**。请将应用配置为只监听本机回环地址。Chora 打开回环 URL，
但应用命令仍可自行控制监听地址，也可以像普通本地命令一样修改文件。
预览产生的变更仍受既有 Review 和交付检查约束，不会自动成为已评审代码。

**Isolated Local** 使用已准备并验证的镜像启动独立应用容器。Agent 容器策略不变。
预览只在 `127.0.0.1` 发布一个端口，本机端口可能与配置的容器内应用端口不同。
容器内应用需要监听 `0.0.0.0` 才能接收转发连接。
容器读取私有源码快照，在临时可写工作区运行；不挂载可写主机目录，不自动传入凭据。
根文件系统只读，内存、CPU 和进程数受限。保留 Docker bridge 出站网络能力。
隔离不可用时不会降级到本机执行。

隔离预览使用启动时的快照。代码更新后需停止并重新启动，才能查看新效果。
容器内生成文件会丢弃，不作为 Agent 输出导回。本切片按 Task 仓库管理单个应用
进程，不包含多服务部署或任意项目专用镜像。

## 生命周期与恢复

切换页面或关闭浏览器标签页不会停止应用。主动停止及正常退出 Workbench 会停止
预览。创建后续 Attempt 或清理 Task 工作区前，会先停止该 Task 的预览。

异常退出后，Chora 校验持久化的进程或容器归属并提供恢复清理，不自动重新启动。
无法证明归属时，不杀死无关进程或删除未经验证的容器。恢复原环境或处理报告的
残留后，再启动新预览。

配置、归属记录和有大小上限的日志保存在 Chora 私有数据根目录中，属于本地运行
状态，不是仓库文件或验收证据。备份恢复请遵循[维护指南](workbench-maintenance.zh-CN.md)，
先停止 Workbench。
