# 本地 Agent 委派

[English](local-delegation.md) · [路线图](../ROADMAP.zh-CN.md)

M3 从一个人在同一台 Mac 上向多个 Agent 执行分配研究工作开始。首片支持软件 Project
中的材料型调研和文档 Task。每项分工成为父任务所在 Room 中的普通 Task，拥有独立的
Run、工作区、结果与评审历史。

## 使用

打开尚未归档、仍开放的调研 Task，在 **Agent 委派** 中填写一至四项分工，每项包含不同的
角色名、标题和要求。选择 **启动委派**，授权系统依次执行。这是独立的明确操作：创建或
启动普通 Task 不会自动委派。父任务不必先执行自己的 Agent Run。

启动后计划不可修改。角色名只标识分工，不代表用户账户、凭据身份或可复用 Agent 配置。
子任务继承父任务的精确材料、所选上下文版本、执行环境、模型选择和冻结的原生能力配置。
后续 Project 修改不会重新绑定这些设置。本地执行仍需当前 No Sandbox 确认；执行环境
不可用时停止推进，不回退到主机或其他模型。Runtime 默认模型仍是默认选择，不保证某个
实际观测模型。

Chora 以系统来源激活每项未被修改的生成执行计划，再启动正常 Pi Run。同一委派内顺序
执行。每个子任务复用既有有界自动重试规则：首次 Attempt 后最多自动重试两次。子任务
不能继续委派。启动其他独立委派需要用户另行操作；这不构成整台机器的并发或 token
支出预算。

## 使用父 Agent 提出的计划

调研 Agent 可以提出分工，无需逐项手填。要求父 Task 在完整的最终 Markdown 结果中，
包含恰好一个独立的以下格式代码块：

````text
```chora-delegation-plan
{"schemaVersion":"chora.delegation-plan.v1","assignments":[{"role":"Researcher","title":"比较方案","requirement":"比较已提供的方案，注明来源并标记未知项。"}]}
```
````

父 Task 仍开放时，选择 **读取 Agent 计划**，检查分工和 **计划来源**，再选择
**按此计划启动委派**，明确授权执行。读取或生成计划不会启动子任务、保存已接受文档，
也不代表人工接受结果。这仍是先提案、再启动的流程。下述专用调研委派会在规划 Run
启动前另行记录执行授权。

服务端只导入最新 Run 当前 Attempt 中可评审的文档结果，核对完整 assistant 事件、
Agent 报告、结果与正文摘要，并在启动时拒绝过期来源。计划需要一至四个不同角色，
正文不超过 32 KiB。未知字段、重复 JSON 键、多个计划块、尾随 JSON 和非法文本均会
被拒绝。格式不能选择资源、执行环境、模型、凭据或进一步委派。无效提案不会创建子任务，
也不会触发自动修复或重新规划。

启动时冻结来源 Run、Attempt、结果、报告、assistant 事件，以及结果、正文和计划摘要。
浏览器提交来源身份和预期结果摘要，由服务端重新读取、校验分工。父任务后续重试或结果
变化不会替换已导入的计划；来源不再是当前结果时会显示提示。停止和重启保留原计划及
相同的子任务执行上限。

## 一次启动规划与执行

在本地 Workbench 创建 Task 时，选择 **规划并委派调研**，填写研究目标和材料，再选择
**启动调研委派**。Task 在正常执行计划激活前冻结明确的规划要求。本次启动持久记录授权：
一次规划 Attempt，以及从合规结果产生的最多四项顺序调研。尚未运行的专用规划 Task
也提供相同操作。

Chora 将授权绑定到唯一父 Run 和 Attempt，只消费该 Run 完整、当前且来源校验通过的
提案，在事务中冻结计划后再执行子任务。普通调研结果或包含计划格式的文本不能授予这种
权限。同一父 Task 的手填计划、提案导入和规划意图互斥。

规划 Attempt 不自动重试。失败或格式错误会阻塞，不创建子任务、不修复输出、不重新规划。
子任务仍复用现有有界重试。**停止调研规划** 立即持久记录停止意图，阻止自动导入，然后
取消绑定的规划 Run。导入完成后，使用 **停止委派** 控制子任务阶段。重启后未完成的规划
进入阻塞；检查既有 Run 后再选择 **恢复调研规划**。恢复保留原授权和身份，不授予新的
Attempt。需要重新规划时创建新 Task。

## 结果与评审

父任务展示每个子任务的当前状态，以及正常执行和评审页面的链接。完成的研究结果展示
原始 Markdown、结果身份和摘要标识。这里汇集各自有来源的结果，不生成新的 Agent
综合结论，也不声称父 Agent 已消费子结果。名为“Reviewer”的角色产出仍是 Agent 提案。

**待评审** 表示各项分工均已完成并产生可评审结果，不表示研究内容经过事实核验或被接受。
请检查证据、未知项与各项结果，再使用既有文档评审操作。委派不会保存已接受 Room
版本、接受结果、启动后续实现 Task，也不会 commit、push 或 merge。若子任务随后改变
状态，汇总将重新提示需要关注。

## 停止与恢复

**停止委派** 先记录停止意图，再取消活动子任务，并阻止下一个子任务自动启动。已准备但
没有运行时会话的子任务可以安全取消。已经运行的检查会等待结束；停止结果不确定时保留
可见状态，不声称执行已结束。停止委派不会取消独立的父 Run，也不会删除已有工作。

Workbench 重启后，运行中的委派变为阻塞。检查子 Run，解决恢复状态，再明确选择
**继续委派**。被中断的停止仍作为停止处理。稳定的子任务和 Run 身份、命令幂等性及事务
父子关联防止重复创建。继续委派不会重置自动重试额度，也不授权执行被修改的计划。停止
的计划保留为历史；新的委派使用新的父 Task。

## 当前边界

这是 M3 的首个本地切片，不代表团队协作整体完成。多人身份、成员与撤销、
递归委派、子任务并行、编码分工与代码整合仍是后续工作。远程位置、通用后台队列、
通知及 token／费用预算仍按实际需求进入 M4。当前本地 Run 由既有服务持有；关闭浏览器
标签页不会把执行转移到其他机器。

验证须区分无凭据的领域、API、持久化、浏览器检查与真实模型旅程。技术完成不能替代最终
产品用户验收，也不代表签名 macOS 分发已合格。
