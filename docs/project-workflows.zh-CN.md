S9 仍处于规划阶段。[路线图](../ROADMAP.zh-CN.md#下一阶段个人工作空间切片)统一维护交付顺序、范围和完成标准。

## 软件项目内的协作

Chora 是人与 Agent 共同开发软件的工作空间。下一步扩展软件 Project 内的调研、
方案决策和文档协作，继续支持编码流程。与软件项目无关的工作、通用办公应用及
通用工作流平台不在本次范围内。

Task 表达有界目标、选定资源和预期结果。结果未来可以是有来源的结论、经过评审的
方案、文档修订或代码变更。这些是场景示例，不要求用户先填写任务类型表单。
仓库变更沿用检查、Review 和交付契约；调研或方案结果不应为了完成任务而制造
Diff、Commit 或 PR。

保持 Project → Room → Task 归属。当前 Project 已可不含仓库，但创建 Task 仍需
选择仓库范围。仓库可选的 Task 与非代码结果完成流程安排在 M2-S9。首个切片使用
明确提供的项目材料及已有、已授权的 Provider 能力，不依赖新文档连接器、编辑器
套件或 Contexere 实现。

## 分清用户的选择

| 概念 | 含义 | 产品处理方式 |
| --- | --- | --- |
| Task | 目标、资源范围和预期结果 | 作为主要入口，不强制工作流分类。 |
| Agent 与模型 | 谁执行工作 | 复用已验证的 Pi 与 Runtime 原生模型发现，不隐含新增 Runtime。 |
| 执行环境 | 在哪里执行、具有什么隔离 | 当前保留本机执行和隔离执行两种选择。 |
| 能力 | 该环境实际可用的工具、Skills 和 MCP 资源 | 复用原生能力与项目配置，披露不可用资源。 |

这些区别不意味着每个 Task 都需要四组选项。Project 保存默认设置；任务入口展示
简短的实际配置摘要，需要时再调整。登记资源或继承配置本身不授予执行权限，也不
扩大资源访问范围。

面向用户的名称为 **本机执行 · 无沙箱** 和 **隔离执行**。持久化技术 ID 仍为
`trusted_local` 和 `isolated_local`；命令、文件路径和策略标识符保持现有名称。
这些名称对应当前相同的两条执行路径，不是额外的模式。

## 现有 profile 的处置

| 现有 profile | 决定 |
| --- | --- |
| `minimal` | 只有实际测试需要时才保留为内部对照配置，不再作为独立用户模式或发布必验项。 |
| `standard` | 有用工具归入默认 Agent 能力配置，不再作为名为 Standard 的产品档位。 |
| `trusted_local` | 保留本机执行路径及明确、持续的无沙箱披露。 |
| `isolated_local` | 保留隔离执行路径、就绪检查及已声明的隔离策略。 |

Minimal/Standard 表达工具组合，不是推理强度或安全级别，不再构成必须交付的产品
矩阵。M2-S4-2 从已排期的资格验证里程碑撤下，不标记为完成或 PASS。新增环境或能力
预设需要先有明确用户需求及有界范围，再进入路线图。

Minimal/Standard 对照夹具可在有助于内部覆盖时保留，但不构成产品兼容承诺。
S8-1 不新增迁移、重开或验证旧 Minimal/Standard 历史的要求，也不引入兼容适配层。
持久化执行 ID、命令、文件路径和策略标识符保持不变。

## 可复用设置与明确执行权限

在 Project 中打开 **默认执行设置**，选择执行环境，以及明确的模型或 **使用 Runtime 默认值**。
未配置的 Project 默认使用隔离执行和 Runtime 默认值。保存本机执行默认值不代表确认
主机访问权限，也不会启动执行。新 Task 展示继承的设置；**为此任务覆盖项目默认值** 只影响
当前 Task，取消覆盖会恢复项目配置。

创建时根据 Project 版本和 Task 覆盖解析实际设置，保存包含各项来源的不可变快照。
表单版本过期时拒绝创建，重新打开任务表单即可加载新默认值。重启后，任务详情仍展示
创建时冻结的设置。修改 Project 不影响已有 Task 的重试、会话恢复或历史。显式后继
模型/环境切换沿用现有规则和来源记录；初始 Task 快照保持不变。Runtime 默认值是一种
选择策略，不代表已经观察到的模型身份。

Skills/MCP 沿用已有的原生启用配置，不新增 Task 级能力勾选：可以在任务中指定 Skill，
也可以由 Agent 自行选择适合的能力。Project 能力引用随 Task 保存，后续尝试继续使用。
Chora 不复制被引用内容和凭证，不冻结全局 Pi 文件，也不承诺 MCP 当前已连接。
现有恢复指纹检查仍拒绝已加载资源发生变化的会话；需要改变 Project 能力引用时创建新任务。

启动前，表单说明执行环境、模型选择和是否支持原生 Skills/MCP。本机执行仍需完整的
**无沙箱** 确认。已保存模型不可用时保留该选择并阻止启动，直到显式修正；不自动回退
到其他模型。隔离必须就绪，不回退到主机执行。保存默认值不会安装工具、复制凭证或
授予资源访问权限。

[Project Skills/MCP](native-capabilities.zh-CN.md) 仅适用于本机执行；隔离执行不会加载
主机能力，其模型与凭证限制继续遵循[隔离执行指南](isolated-local.zh-CN.md)。

## 首条项目协作流程

下一条需要证明的流程是：

```text
项目问题 + 明确选定的材料
→ 有来源的调研与方案提议
→ 人工反馈和修订
→ 被接受的结论或项目文档修订
→ 后续实现 Task 显式引用
```

M2-S9 先由单个用户与现有 Agent 完成这条流程，适用处复用 Task、Result、Artifact、
Decision、Review 和上下文选择机制，不另建 Issue、审批或知识引擎。缺失证据继续
标为未知，Agent 提案与人的决定区分。接受结论或文档不授权仓库写入、对外发布或
启动后续实现任务。

保存来源引用、修订身份、反馈和评审状态，确保重启后可以继续。后续 Task 显式选择
已接受版本，之后的编辑不能改变其冻结输入。材料保留在所属 Room，直到被明确引用
或在 Project 内共享。已有编码任务继续使用 Diff/检查/SCM 路径；Task Board 必须准确
展示两类工作，不给文档结果虚构代码交付阶段。

团队权限和委派仍在 M3，后台与远程工作仍在 M4；正式 macOS 分发属于独立发布路线。
验证下一条个人项目工作流程不依赖这些后续能力。
